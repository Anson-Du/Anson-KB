# 编译规则（COMPILE_RULES）

> 本文件是知识库编译管线的**白盒明文规则**：人随时改，AI 每次编译前必须先完整读取本文件并遵守。
> 机制源自 Yiki 的「采集→原料→编译→知识→查询→策展」管道（2026-09-15 分享版），按 Anson 实际目录体系改造。
> 版本：v1.0｜生效：2026-09-25｜维护人：Anson

## 一、核心原则

**知识库不靠"收藏"靠"编译"**：原始材料只进不改（00–08 目录即原料层），AI 按本规则定期把原料提炼成结构化知识页（wiki/），查询时先查知识层、再查原料层，人只做每周约 10 分钟的策展纠错。

| # | 原则 | 一句话解释 |
|---|---|---|
| 1 | **原料与知识分离** | 00–08 目录只存原文证据（AI 永不修改），wiki/ 存提炼结果——可追溯、可纠错 |
| 2 | **规则白盒可进化** | 编译规则就是本文件，人改完下次编译即生效 |
| 3 | **自动兜底 + 手动主动** | 定时调度保证"不漏"（launchd 每日同步 + 每周自动编译），触发词保证"想用即用" |
| 4 | **人机分工** | AI 干 95%（记录/整理/编译/检索），人干策展/纠错/定方向 |

## 二、AI 五条红线（编译的行为边界，违反任何一条即失败）

1. ❌ **修改原料层任何文件**——`00_收件箱/ ~ 08_媒体素材/`、`codebuddy-memory/`、`CodeBuddy旧对话/` 中的文件一律只读
2. ❌ **覆盖人类手改过的 wiki/ 内容**——编译绝不覆盖人工编辑；不确定是否人工改过时，跳过该页并在 log.md 记录待人工确认
3. ❌ **删除旧结论**——只能标注（见"矛盾与过时标注"），不能抹除
4. ❌ **编造来源**——每条结论的来源必须真实指向原料层文件路径
5. ❌ **把未经确认的内容写入页面**——拿不准的写进 log.md 待定区，等人圈选

**wiki 只由编译管线生成条目；人手写/整理的任何文档一律进原料层（如 `00_收件箱/`），不进 wiki**——拿不准就放原料层。

## 三、页面类型（4 类，文件名前缀区分）

| 前缀 | 类型 | 定义 | 更新方式 |
|---|---|---|---|
| `主题_` | 主题页 | 持续关注的方向/领域 | 随资料累积持续更新，知识库的"骨架" |
| `实体_` | 实体页 | 具体的人、组织、项目、工具 | 一个实体一页，反复出现时合并更新 |
| `概念_` | 概念页 | 需要长期沉淀的技术/方法论概念 | 定义 + 关联资料 + 个人理解 |
| `来源_` | 来源页 | 单篇高质量原始资料的整理 | 一篇一页，是其他页面的"证据底稿" |

### 页面统一模板

```markdown
# <前缀>页面名

## 概述
（是什么 + 为什么重要，3-5 句）

## 关键信息
（结构化要点，表格/分点）

## 时间线
| 日期 | 事件 |

## 来源
- [[原料层相对路径]]（说明该来源支撑了哪条结论）

## 关联页面
- [[主题_某主题]]、[[实体_某实体]]（Obsidian 双链）
```

## 四、素材差异化编译策略（速扫分级，控制精读成本）

| 素材源（原料层位置） | 编译策略 |
|---|---|
| `01_工作/RoboX/01–09`（RoboX 全部编号目录） | 主力管道：增量更新 RoboX 各主题域页面 |
| `01_工作/Datawhale/01–07`（Datawhale 全部） | 增量更新 Datawhale 生态主题域页面 |
| 会议录音转写（各 `*纪要*/听记/转写*` 目录、清理版 docx） | 先速扫标题+摘要分级：🔴 高价值 → 精读提炼进 wiki；🟡⚪ 例行 → 只记入对应主题页"时间线"，不建独立页 |
| 研究报告（`01_工作/研究报告/`、`05_具身智能行业与竞对/`） | 高价值 PDF 提炼为"来源_"页并更新主题页 |

| `codebuddy-memory/`（AI 记忆镜像） | 仅供编译时参考 AI 画像，本身不建页 |
| `CodeBuddy旧对话/`（8 个旧对话导出） | 有价值的（ARM 概念、datawhale 背景、RoboX 投资价值）提炼进对应主题页 |

## 五、矛盾与过时标注（知识可纠错的关键）

新旧信息冲突时**不删除旧结论**，在新结论旁标注：

```
> ⚠️ 与 X 矛盾（旧结论见下·历史结论小节）
```

过时结论标注 `> ⚠️ 可能过时（日期 后有更新）`。旧结论一律保留在"历史结论"小节。目的：**知识可追溯、AI 幻觉不会永久刻入**。

## 六、查询优先级（写入 AI 用户级长期记忆，每个会话生效）

```
① wiki/ 已编译知识（快、结构化、带双链）
    │ 没有或要核实
② 原料层原文（00-08 目录，可全文搜索）
    │
③ 网络/其他外部源
```

- 优质回答可经 Anson 确认后**回流**为新页面或追加到既有页面（查询也是进料）

## 七、编译流程（每次编译的标准动作）

1. 完整读取 `schema/COMPILE_RULES.md` + `schema/FOLDER_STRUCTURE.md` + `schema/ERRATA.md`
2. 读取 `wiki/log.md` 了解上次编译进度（增量起点）
3. 扫描原料层新增/变更文件（可用 `git log --since` 辅助定位新进料）
4. 按"素材差异化编译策略"分级、提炼、写/更新 wiki 页面
5. 更新 `wiki/index.md`（新页面挂链）与 `wiki/log.md`（追加编译记录）
6. `git add -A && git commit`（提交信息注明编译范围）

## 八、归档硬规则（进料时遵守，编译时校验）

- **只增不改**：文件入库即固化（时间/标题），修订版只增新副本
- **命名规范**：新入库材料统一 `YYYYMMDD_标题`；**现有目录结构原样保留**（渐进策略，不做历史重命名）
- **原文原则**：原料层只放原文或全文转写，个人总结写进 wiki
- **勘误套用**：编译输出前对照 `ERRATA.md` 替换错误名词
